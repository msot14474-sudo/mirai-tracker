# Interface review — 30 October 2026

## Scope and method

Reviewed the role-specific navigation, wording, content hierarchy and responsive layouts using existing evaluator data. The candidate frontend build was loaded against the deployed API for campus manager, faculty and student accounts. Administrator/program-manager screens were reviewed in the existing signed-in browser session, which carries both roles.

Desktop checks used a 1440 × 1000 viewport; phone checks used 390 × 844. A final 1440 × 745 laptop check caught and corrected prompt-card crowding above the AI composer. Browser inspection included page-width measurements, screenshots and rendered text. Repository review covered empty states, report instructions, planning labels and subject detail rendering.

This is a UI review, not a claim that every possible data combination or account permission has been tested. Production records were not edited, users were not created, and no messages were sent during the review.

## Findings and fixes

| Area | Finding | Change |
| --- | --- | --- |
| AI insights | Oversized undifferentiated chat space, plain prompts and a redundant Academic context and priorities panel | Removed the context panel; added a clear assistant header, three action cards, readable conversation styling and a compact composer. Phone cards fit above the composer. |
| User access | Campus team content widened a 390px page to 610px | Constrained the directory and table wrapper. The page now measures 390px; the table scrolls inside its own region. |
| User access | Add/edit controls followed the account list on narrow screens | Placed the editor before the list at phone sizes. |
| User access | Account count briefly displayed zero during loading | Display Loading accounts or Accounts unavailable until a valid count is known. |
| Empty states | Unexplained 01, 02, 11, 12 and 13 markers | Removed these markers from semester, timetable, plan, planned-date, progress, exam, student and account empty states. Instructional step numbers remain where they indicate actual steps. |
| Planned dates | Technical “Ordered topic minutes ÷ usable scheduled minutes” text looked like a formula for dates | Replaced it with “Topics follow your lesson plan and available class times.” |
| Reports and progress | Long access and date-filter explanations | Shortened wording while retaining the distinction between filtered records, current coverage and future teaching capacity. |
| Daily logging | A promotional Under-one-minute flow banner duplicated instructions | Removed the banner and retained the direct logging guidance. |
| Exam readiness | Neutral calculation guidance used warning colours | Applied a neutral information treatment; genuine risk indicators retain their colours. |
| Student overview | Introductory wording and vertically stacked batch metadata delayed access to subjects on phones | Shortened the introduction and made the batch information more compact. |
| Subject exam syllabus | Long flat lists repeated generic topic names without their units | Grouped topics in expandable unit sections, retaining coverage for every topic. |
| Management mobile header | Ellipsis could hide the current page name | Allowed the header title to wrap. |
| Subject directory | Two paragraphs repeated the same explanation | Kept one main description and shortened the directory instruction. |

## Verification

- Initial automated sweep: 22 role/page combinations at desktop and phone widths (44 viewport observations).
- One page-wide overflow found: User access on a phone, 610px content in a 390px viewport.
- Targeted recheck: eight changed role/page combinations at both sizes. All measured at their viewport width, with no page-wide horizontal overflow detected.
- Frontend regression suite: **38 test files, 161 tests passed**.
- After the final subject-syllabus grouping change: **17 focused tests passed**, covering Subjects and AI insights.
- TypeScript checking and production frontend build passed.
- AI tests include removal of the academic-context panel, question submission, role-appropriate prompts, history and error handling.

Screenshots and local browser observations are saved in `outputs/qa/ui-audit-20261030/` (ignored working evidence, not a public account-data export).

## Remaining design opportunities

- Wide analytical tables intentionally scroll within their table region. A condensed phone card view would be a separate improvement; removing columns would hide useful information.
- Demo subject and faculty names are lengthy and visibly marked Demo. They were retained because they identify evaluator data, rather than being interface errors.
- Large syllabus and calendar pages still require vertical scrolling. Their content should stay available; further progressive disclosure can be considered without hiding editing controls.
- The administrator and program-manager review used a combined-role account. A separate single-role program-manager session was not available through the saved evaluator credentials.
- Destructive actions, actual imports, email delivery, export generation and every validation/error branch were not exercised in production in this visual pass. Existing automated tests cover selected behavior; this review does not replace a full functional or security audit.
