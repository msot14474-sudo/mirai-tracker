# Interface review — 30 October 2026

## Scope and method

Reviewed the role-specific navigation, wording, content hierarchy and responsive layouts using existing evaluator data. The candidate frontend build was loaded against the deployed API for campus manager, faculty and student accounts. Administrator/program-manager screens were reviewed in the existing signed-in browser session, which carries both roles.

Desktop checks used a 1440 × 1000 viewport; phone checks used 390 × 844. A final 1440 × 745 laptop check caught and corrected prompt-card crowding above the AI composer. Browser inspection included page-width measurements, screenshots and rendered text. Repository review covered empty states, report instructions, planning labels and subject detail rendering.

This is a UI review, not a claim that every possible data combination or account permission has been tested. Production records were not edited, users were not created, and no messages were sent during the review.

## Remaining design opportunities

- The report and campus-team table findings have been resolved with labelled phone cards. Other genuinely wide data previews retain internal scrolling so no values are removed.
- Demo subject and faculty names are lengthy and visibly marked Demo. They were retained because they identify evaluator data, rather than being interface errors.
- Large syllabus and calendar pages still require vertical scrolling. Their content should stay available; further progressive disclosure can be considered without hiding editing controls.
- The administrator and program-manager review used a combined-role account. A separate single-role program-manager session was not available through the saved evaluator credentials.
- Destructive actions, actual imports, email delivery, export generation and every validation/error branch were not exercised in production in this visual pass. Existing automated tests cover selected behavior; this review does not replace a full functional or security audit.

## Mobile remediation follow-up

The mobile follow-up goes beyond viewport screenshots: it opens navigation and account menus, changes pages, expands records, switches tabs and checks editable form states without committing changes to live academic records.

### Fixes implemented

- Fixed the shared header clipping both mobile navigation and the account menu. Popovers now fit the viewport, including 320px phones; navigation remains scrollable. Account actions use larger touch targets. Tapping outside, choosing a destination and Escape dismiss the menus; Escape restores trigger focus.
- Converted report and campus-team rows to labelled phone cards, preserving every value and desktop table semantics. Long subject, faculty and batch names wrap instead of extending off-screen.
- Added month navigation to the semester calendar, with every date still reachable and holiday/exam editing retained.
- Grouped subject teaching plans into expandable units; made lecture/topic records readable as labelled mobile cards. Subject tabs wrap and support keyboard navigation.
- Grouped student teaching plans by unit and made covered work and exam syllabus expandable.
- Fixed overlapping topic-remove/minutes controls in daily logging, improved mobile field spacing and labelled planned-date values.
- Account selection brings the editor into view instead of leaving the user at the old list position.
- Added a phone-friendly timetable presentation and collapsible planned-date history to reduce long initial views.
- Weekly summaries now lock background scrolling, contain keyboard focus, close with Escape and restore focus. The dialog heading and close control fit narrow screens.
- Removed decorative help-card numbers and shortened redundant weekly-summary text.

## Mobile dropdown follow-up

Rechecked the reported menus rather than assuming the earlier viewport pass was sufficient. The live account and navigation buttons opened in Chrome at phone width, but navigation could retain an old scroll position, and the underlying long page could move while menus were open.

Changes:
- Opening navigation resets its own scroll position so the first options remain discoverable.
- Mobile navigation uses a positioned wrapper instead of `display: contents`; its scroll area stays bounded by the phone viewport.
- A dismissible backdrop prevents accidental interaction with the underlying page; document scrolling is locked until the menu closes.
- Account and navigation menus remain mutually exclusive. Escape/backdrop restore focus, account arrow keys work, Tab stays within the open mobile header, and returning to desktop closes the overlay and restores scrolling.
- Semester subject checkboxes now occupy separate, tappable rows instead of running together.
- Report filters use full-width fields on narrow phones so campus and semester selections are easier to read.

Regression coverage includes faculty, campus-manager and student menu scrolling/dismissal, keyboard navigation, resize and cleanup. All 39 frontend files / 173 tests passed. Live browser checks are responsive Chrome checks; this does not claim a physical iPhone/Safari test.

A short-phone deep-scroll check then exposed the sticky header moving out of view when root scrolling was locked. The phone header is now fixed with matching content spacing. A local fixture check at 320 × 568 verified the header remains at y=0 and the page stays at scrollY=1145.5 through opening and dismissing the menu; navigating to My account returns to the top normally. This fixture check used no live records.
